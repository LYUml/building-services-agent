# mep-electrical

For a single-voltage three-phase constant-PQ wye network, use docs/THREE_PHASE_NETWORKS.md and the isolated pinned pandapower runtime through `scripts/run_three_phase.py`. Explicit source sequence data, per-phase electrical kW/kvar, line sequence impedances/lengths and current/voltage study targets are required. Inspect independent branch/node/complex-power checks and native input correspondence in study.json. A converged target failure remains fail; source-hash association does not verify interpretation. This standalone path is not yet a workflow adapter or CAD/BIM binding, and does not cover physical neutral/harmonics, transformers, protection, motor starting or Hong Kong conformity. Do not treat its study targets as verified cable ratings or feed its loads into the single-phase project format below.

Use docs/PROJECT_FORMAT.md. Populate equipment and circuit data from the brief, inspected geometry, measured routes and authoritative references. CLI: bsa validate <project.json>; bsa run <project.json> --out <new-run-directory>.
The calculation engine uses sum(kW/PF)*1000 for connected VA, demand VA / line-neutral V for Ib, tabulated ampacity times correction factor for Iz, and mV/A/m * Ib * route /1000 for voltage drop. Mixed load VA summation is conservative scalar aggregation, not a phasor solution. This slice covers single-phase circuits only; do not map three-phase loads to it.
Review Ib <= In <= Iz and voltage drop, then independently address fault disconnection, breaker breaking capacity, overload conventions, coordination, neutral/harmonics, incomer demand and earthing as applicable. No table values are embedded; cite chosen coefficients and conditions. Failed checks require changes, not an unchecked report.

For full installation-path voltage drop and jurisdiction checks use ../mep-regulations/SKILL.md and docs/ELECTRICAL_PATHS.md. `electrical_regulations` derives the supported single-phase feeder/branch budget directly from original inputs; branch-only results are insufficient. Retain explicit origin/topology, shared downstream loads and coefficient sources, and never clear failed branch protection because a selected voltage-drop rule passes. Full feeder protection and three-phase analysis remain unsupported by this adapter.

For supported TN bolted-fault checks, read docs/ELECTRICAL_FAULTS.md and use `electrical_fault` or `bsa.electrical_fault` with explicit fault source data for every circuit. Keep minimum hot L-PE loop current separate from maximum prospective fault at the device. Require actual nominal-voltage/current applicability, total-clearing and full-interval let-through energy guarantees; do not infer B/C/D defaults or I2t from prospective current squared times trip time. Null/uncovered data stays pending. CPC thermal area alone does not select a compliant conductor; source k/time limits, mechanical minima, actual editions/clauses and remaining protection/earthing gates separately.
DXF is a metre-coordinate overlay. It does not prove native DWG fidelity or lighting photometry. For native AutoCAD work, verify active document full path immediately before every write; use a versioned copy. Prove units, layers, scale and a three-device sample with actual save/reopen and plot review before mass placement. Keep unsaved user documents open; do not restart CAD.
Generate schedules and diagram labels from the same IDs. Reconcile geometry counts with device data after native authoring.

For an existing base, read docs/DRAWING_INTAKE.md and docs/CAD_OVERLAY.md. Use `base_overlay` with a reviewed source-hash/known-dimension selection and explicit rigid coordinate mapping. Keep devices/labels on separate reserved layers, compare preserved base records and independently reopen native DWG when requested. For fixed-scale sheets, provide the explicit A4 window, denominator and LINE reference; verify its physical PDF length and visually inspect the exact output. Unsupported base entities/xrefs and layout/placement collisions require resolution, not silent deletion or full-fidelity claims.

For coordinated electrical/CAD/IFC work, read docs/COORDINATION.md and use `python -m bsa.coordination <project.json> --geometry <geometry.json> --out <new-run>`, or the electrical_coordination workflow adapter. Keep all electrical XY/power/PF/circuit data in the common project; add only explicit missing spatial dimensions and heights through the geometry companion. Review both saved artifacts and coordination.json; cross-artifact consistency does not replace protection/photometry or visual review.

For pump operating estimates, read docs/PUMP_ELECTRICAL.md and use `pump_electrical` only with explicit pump/source-port GUIDs, electrical ID, centre-position basis and operating PF. Require verified pump source/artifact hashes and replay, actual IFC network/connection reconciliation and saved property/schema checks. Preserve the baseline load scenario and all circuit hardware; keep the operating estimate separate from nameplate/design and starting requirements. A lower operating current cannot clear a failed baseline check. Other devices and electrical IFC topology remain unbound unless separately verified.
