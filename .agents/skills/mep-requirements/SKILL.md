For drawing samples or annotated reference sets, establish their role before extracting requirements. Presentation examples do not automatically add systems, dimensions, equipment ratings or code obligations to the actual brief. Compare the original rendered pages and retain a page correspondence when the annotated set omits sheets or crops/enlarges regions; equal page numbers need not represent the same drawing. Colored highlights without a legend are not authenticated system classifications or correction instructions. Image-only pages remain graphical sources, not blank pages; preserve extraction blockers and actual visual notes rather than manufacturing text quotes.

# mep-requirements

Read the actual document, including drawing notes and deliverable list; cite page/section for each requirement. Create requirements.json with id, source_document, locator, requirement, discipline, deliverable, verification_method, status and evidence. Unknown values must remain unresolved.
Create a project data file using docs/PROJECT_FORMAT.md for supported electrical tasks. Distinguish measured inputs, manufacturer data, course-given values, design targets and explicit assumptions. A proposed assumption is not a supplied fact. Record thermal kW, electrical kW and kVA separately.
Before geometry, prove source units and scale using a known dimension and identify WCS/local coordinate transformation. Before simulation, collect climate/weather, constructions, infiltration, occupancy/load schedules and HVAC control assumptions. Missing inputs may permit an explicitly labelled scenario, but not an asserted measured answer.
Separate assignment-permitted design choices from missing supplied facts. Document chosen sites/geometry/programs as design decisions; do not label them measured inputs or invent them as course-given data. Preserve approximate targets with unresolved acceptance bands instead of silently converting them into exact minima. Preserve fictional course/game currencies separately from engineering cost estimates.
Keep supplied files unchanged and record hashes. Do not upload private source documents to external services without task authorization.

For local-code requirements use ../mep-regulations/SKILL.md. Record jurisdiction, building/works scope, relevant dates, selected editions and applicability evidence before assigning numeric limits. Keep regulatory clauses distinct from course targets and contract specifications. Map unimplemented disciplines/clauses to explicit pending review requirements; a narrow rule pack cannot replace the brief's full scope.

For DWG/DXF input, read docs/DRAWING_INTAKE.md and use `bsa.cad_intake` or a `drawing_intake` workflow task. Inventory first, then review and hash-bind an explicit selection of boundary handles plus a known independent LINE dimension. Do not infer room meaning from a closed outline, derive scale from labels alone, or silently ignore nested blocks/xrefs. Unitless, curved or unsupported geometry remains unresolved. Native export and polygon measurements do not prove DWG fidelity or plot quality.

## Executable intake and planning

To bootstrap a new source-linked plan use `python -m bsa.workflow_draft <brief> --supplement <rubric> --out <project-root/plan.json>` (optional primary --ocr). Sources must be under the plan directory. This conservative scaffold quotes every extracted passage, classifies all as requirements and creates blocked manual interpretation tasks; it does not interpret semantics or select tools. Read every source, split compound requirements, justify context dispositions, inspect extraction issues and replace placeholders with actual sourced tasks/acceptance. Resolve interpretation blockers from evidence; never simply remove them to claim completion. Exit 2 means interpretation remains pending even when the draft was saved. Empty extraction creates no plan; unreviewed extraction issues remain unacknowledged and prevent execution.

For separate rubrics/appendices, use repeated intake `--supplement` arguments and `supplemental_briefs` in the plan; cover every document's passages and extraction issues. For known missing parameters or conflicting instructions, declare source-linked `unresolved_inputs` with the affected task IDs as documented in docs/WORKFLOWS.md. These tasks remain unexecuted, independent tasks may continue, and downstream pass gates remain active. Keep requirement coverage as well as the issue record. Do not fill gaps with invented adapter inputs or erase an issue merely to permit execution; resolve from actual evidence, revise the basis/plan and preserve the previous run. The register does not discover undeclared gaps or verify semantic consistency of a proposed resolution.
Read docs/WORKFLOWS.md and docs/DOCUMENT_INTAKE.md. Run `python -m bsa.workflow intake <brief> --out <new-intake.json>` for Markdown, text, PDF or DOCX. Interpret every indexed passage, classify requirement/context with care, author a plan following examples/workflow-plan.json, and populate the appropriate source-backed project JSON. Quotes must match the actual extracted source. `python -m bsa.workflow validate <plan.json>` checks source linkage and coverage, not semantic correctness. Keep missing inputs explicit; do not silently discard drawing notes, tables or pages.

Inspect every extraction issue against actual source pages or Word rendering, then record specific `document_review` notes. Word XML locators are not page numbers. Tracked changes and pages without extracted text block planning. For PDF OCR, use the optional local `bsa.ocr` adapter, retain raw text/boxes/confidence and bind sidecar/images to source hashes. Review symbols, decimal points and units visually; confidence does not prove correctness. Never silently normalize a mistaken OCR equipment ID into an assumed design value. Mixed readable text/image pages still need figure review.


When a brief supplies BIM information requirements or an IDS file, record its source/version, applicable entity scope and required attributes separately from physical/performance/regulatory requirements. Use docs/IDS_WORKFLOW.md for the information-check task; do not substitute the repository's synthetic pump-presence contract for an assignment contract. For pump selection, distinguish supplied candidate/product curves from design-flow targets, and request missing product/operating evidence rather than deriving motor ratings or manufacturer dimensions from a curve.

For an explicitly reviewed source-specific work decomposition, bsa.work_plan_review.apply can replace only the untouched generic interpretation scaffold. Require exact source/text hashes, every technical passage mapped, original quotes/dispositions retained and concrete unresolved engineering packages with prerequisites. Preserve existing engineering gaps. Record the review via planning_records. The public --apply-work-plan example groups 34 passages into 14 pending packages; reduced task count is not reduced requirement scope or completed engineering. See docs/CONCEPT_SPACES.md.

For bounded GIS context use docs/GIS_CONTEXT.md and scripts/stage_chicago_footprints.py. Require raw snapshot/query/count/hash coverage, explicit source CRS/projection and independent metre/area checks. Dataset metadata dates and source-data dates differ; historical footprints are not current site surveys or vacant parcels. Never infer missing heights from storeys or ambiguous Z fields. Official county metadata discovery is not a verified geometry/height integration; retain full 3D/current-context/IFC placement and shading gaps.
