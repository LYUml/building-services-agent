# Saved continuous cable route drawing

`bsa.cable_route_drawing` is a thin saved-geometry-to-ezdxf adapter for exactly one checked quarter-circle plus tangent-straight cable. It uses the existing electrical IFC reader's mandatory native connected-solid, independent volume/bounds/centroid, ports, anchors and actual length checks before drafting. It does not take schematic Graphviz positions as physical route geometry.

Supply a prepared electrical project, the exact saved IFC and binding, and drawing settings with `projection_axes`, `annotation_height_m` and `source` (the existing drawing-settings contract). Example:

```powershell
.venv/Scripts/python -m bsa.cable_route_drawing runs/continuous-cable-native-workflow-v1/workflow/study/project.json --ifc runs/continuous-cable-native-workflow-v1/combined/model.ifc --binding runs/continuous-cable-native-workflow-v1/combined/binding.json --settings runs/cable-route-settings-v1.json --out runs/new-cable-route
```

The settings used in the executed trial were `{"projection_axes":["X","Z"],"annotation_height_m":0.04,"source":"Synthetic drafting settings; no installation acceptance"}`. Text height and drawing scale are drafting assumptions, not service dimensions or regulatory requirements.

The DXF contains actual circular ARC and straight LINE axes, circular envelope OD outlines, a radial graphic, straight-length LINE/TEXT dimension graphics, true total/arc lengths, bend radius, plane coordinate and full cable IFC GUID. All 16 generated entities carry the actual same cable GUID, rather than inventing separate IFC objects for its pieces. Dimension graphics are not associative CAD DIMENSION entities; regenerate after source changes. The curved piece is never replaced by an endpoint chord. End-on/oblique projections, nonplanar routes and unsupported geometry fail. The selected cable is included; other physical model GUIDs are explicitly listed as omitted and the printed scope note says so. This is not a coordination or installation drawing.

## Reuse and native delivery

The existing hollow-pipe route reader/drawer was inspected before implementation. Its wall/bore labels and per-piece GUID annotation layout are incompatible with a single solid continuous cable, so they are not fabricated. Reused engines/tools: pinned IfcOpenShell 0.8.5 and Manifold 3.5.4 through the existing inspector, ezdxf 1.4.5, existing snapshot/reconcile and IFC identity readers, and `bsa.ifc_native` for guarded copy-only AutoCAD SAVEAS, independent reopen/export, geometry/annotation/XDATA reconciliation and fixed-scale PDF measurement. Existing upstream attribution/licenses apply; no new dependency or geometry kernel was added.

Native settings add only the supported `BSA_CABLE_AXIS` reference layer and `cable-route` drawing name. A selected nonzero saved straight axis is the reference; a chord is not substituted. The executed settings used source text identifying the synthetic X/Z view, `window_drawing_units=[-2.3,1.1,2.7,2.9]`, `scale_denominator=20`, the actual `reference_ifc_guid`, `reference_layer="BSA_CABLE_AXIS"`, `drawing_name="cable-route"`, and `pdf_tolerance_mm=0.2`. Invoke `.venv/Scripts/python -m bsa.ifc_native <route.dxf> --settings <native-settings.json> --out <new-native-directory>` with the installed AutoCAD runtime.

Actual final outputs are in `runs/cable-route-drawing-v2` and `runs/cable-route-native-v2`. The first printed trial exposed insufficient dimension text spacing; it is retained, and v2 separates the text from the line. Saved/reopened geometry, all 16 entity identities/annotations and metre units pass. The 2 m source straight printed at 1:20 measures 99.991333 mm versus 100 mm expected. The final PDF was rendered and visually inspected: the arc/straight/OD geometry is continuous, dimension text is separated, and the source length/radius/scope notes are readable. Duplicate PDF PageMode warning remains; no PDF-conformance assertion is made.

Four projection tests pass (multiple rotations and swapped axes, end-on rejection, wrong midpoint rejection and nonplanar straight rejection). Existing native tests: four pass and one local-runtime-dependent test skips; the separate actual new native trial above executed successfully. An upstream IFC destructor warning occurred while the existing test suite completed. Evidence is in `evidence/pandapower/cable-route-drawing.json`.

Pending: workflow registration with same-model study/bend/coordination gates, obstacle-inclusive drawings and collision-free dimension/label layout for arbitrary rotations, associative/formal dimensions, additional route pieces, manufacturer/support/joint details, actual drawing conventions and complete installation/regulatory/engineering acceptance. Standalone output is not release authorization and does not clear the old missing distribution hardware.

## Workflow release integration

Workflow kind `cable_route_drawing` now takes `depends_on` on an earlier `three_phase_ifc_project`, explicit `ifc`, `binding`, drawing `settings`, `native_settings` and `requires_pass`. It forbids a replacement project. Both a `three_phase_bend_limits` and a `three_phase_coordination` prerequisite are mandatory, directly or transitively. All associated electrical checks must inherit the same numerical producer. IFC plus cable-binding byte identities must match that producer and the route consumer; identical copies are allowed. Inventory prerequisites inspect the route task's explicit model rather than mistaking the numerical producer for an IFC export.

At execution, missing/failed numerical study, unavailable AutoCAD or unresolved prerequisites leave the route pending without invoking its author. Before drawing, the producer artifact tree and associated check artifact trees are rechecked against in-memory hashes. The verified study context and exact derived project are inherited; no separate user-supplied study/project can be substituted. The route DXF then reaches the existing native adapter inside the same task. Technical pass requires saved identity/geometry, native reopen and physical PDF reference passes. Actual page/installation/engineering review remains separate. Delivery context recomputes numerical and model bindings.

Run the synthetic end-to-end case with `.venv/Scripts/python scripts/run_continuous_cable_workflow.py --out runs/new-route-workflow --python tools/pandapower-runtime/Scripts/python.exe --route --autocad "C:/Program Files/Autodesk/AutoCAD 2027/accoreconsole.exe"`. Graphviz is not needed for this physical route view. Add `--inside-limit .295` for the failed-radius control; omit AutoCAD when exercising a block without native output.

Actual `runs/cable-route-workflow-native-v1` passed study, bend, coordination and native route drawing; manual review remains pending. The generated PDF was separately rendered and inspected: correct true-arc/OD geometry, readable source notes and separated straight dimension text; the 2 m reference measures 99.991333 mm at 1:20. Actual `runs/cable-route-workflow-failed-bend-v1` passed numerical/coordination checks but failed the inside-radius target, leaving drawing pending with no drawing directory. Both runs passed workflow integrity and current delivery-context verification. Seven new binding/inventory/gate tests and five existing calculation-schematic workflow tests passed, including actual isolated-runtime target and artifact-block controls.

An actual deliberate artifact-tamper control in `runs/cable-route-workflow-tamper-v1` freshly executed study/bend/coordination, then used a test hook on `bsa.input_issues.blockers` to replace the generated bend/bend-limits.json with `{}` immediately before the drawing task. ## Source-checked obstacle projections

The drawing CLI now accepts optional `--obstacles <inventory.json>`, and the workflow task accepts `obstacles` pointing to that same source inventory. The synthetic runner adds `--include-obstacles` together with `--route`. Existing selected-cable behavior remains available when no inventory is declared.

`bsa.obstacle_projection` reuses `ifc_obstacles.prepare`, source digests, upstream native geometry and the existing `box_geometry.box_mesh` validator. It checks exact project-derived obstacle GUID/name/class, source/inventory hashes and kinds, native closed box volume and world origin/size before projecting. Native bounds must match the declared source; properties alone cannot stand in for geometry. Sources and inspector code join workflow input pins, and conflicting shared input hashes between cable and obstacle inspections are rejected. No new engine/dependency is introduced.

Obstacle-inclusive mode requires every physical non-feature/non-virtual element to be either the selected cable or a source-checked box. An extra unlisted equipment object prevents drawing rather than silently disappearing. Box outline entities and depth notes carry the actual obstacle GUID; cable entities retain the cable GUID. Projected rectangles use actual world bounds. Printed notes identify the omitted axis and exact box depth interval alongside the cable route plane and explicitly state that projection is not a clash test. A box outside the plane is projected deliberately, never represented as coplanar geometry or independently accepted clearance.

Actual `runs/cable-route-obstacles-native-v1` passed study, bend, represented-model 3D coordination and native drawing. Two physical elements were included, zero omitted. AutoCAD reopen verified all 21 linked entities; the 2 m reference measured 99.991333 mm at 1:20. The actual PDF was rendered and inspected: continuous cable/OD geometry, projected box, readable depth interval and separated straight dimension. The box overlaps the cable in X/Z projection but its Y interval is [0.100000,0.140000] m while the cable centreline plane is Y=0 m. The separate same-model 3D check found no intersection or target-clearance failure; the printed overlap is not waived or treated as a physical connection. Full workflow integrity and delivery context pass.

Six native/source/coverage tests pass, including shifted box, wrong provenance, wrong identity, invalid projection and extra unlisted physical equipment blocking before output. Four existing projection tests and seven workflow identity tests also pass (17 distinct tests). Evidence: `evidence/pandapower/cable-route-obstacles.json`. Upstream EXPRESS ResourceWarning and duplicate PDF PageMode warning remain explicit.

This supersedes obstacle omission only when the source inventory is supplied and complete for the supported model. ## Independent saved-entity audit

`bsa.cable_route_audit.audit_saved` reads the actual DXF against already source-checked cable/box geometry. It does not call the writer or accept the writer's success flags. Its caller must supply the checked geometry; the raw function alone does not authenticate a hand-written expected record or re-inspect IFC. The drawing adapter supplies its freshly checked model values, and the workflow pins the relevant inputs and audit code.

The audit independently recomputes the quarter's angle interval from its three points, true arc-plus-straight length, expected centreline/OD curves, dimension graphics, dimensional/source/depth text and IFC coverage. It requires the exact multiset of supported model entities and their prescribed geometry/positions. It also checks metre units, WCS XY geometry, finite coordinates at the supported precision, text height/alignment/rotation/width/obliqueness, entity visibility, raw and loaded paper-space markers, and on/thawed/plot-enabled layers. Existing raw DXF tag handling is reused from route_drawing_qa, avoiding normalized-away marker acceptance. No new engine/dependency was added; the hollow-pipe audit's distinct-piece identity/label contract is not fabricated for this continuous cable.

The author runs this audit after saving/reopening its DXF. Workflow cable_route_drawing also runs it against AutoCAD's independently reopened/exported source-export.dxf; any mismatch fails the task. Both result records remain separate from actual PDF review. Fonts, arbitrary graphic style effects, crowded-layout quality, associative dimensions and full installation acceptance are not established by matching prescribed entities.

Ten saved-entity tests pass: ordinary source-checked output, modified centreline radius, modified OD with unchanged axis, chord substitution, false total-length text, hidden entity, nonplot layer, wrong GUID, moved dimension text and raw paper-space marker. Four projection and seven workflow binding tests also pass (21 distinct tests). The full source-driven native trial and its before/after audit records are retained separately in executed evidence.

Actual `runs/cable-route-audited-native-v1` freshly passed study, bend, coordination and route delivery. Source DXF and AutoCAD reopen/export DXF each passed the independent 21-entity audit. The 2 m reference measured 99.991333 mm at 1:20. The current PDF was rendered and visually inspected for readable notes/depth, continuous route/OD geometry and separated dimension text; both represented elements are included. Workflow integrity and current delivery context passed. Records and hashes are in `evidence/pandapower/cable-route-audit.json`; duplicate PDF PageMode warning is retained, with full engineering review pending.
