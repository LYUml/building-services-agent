# Steady circulation with an explicit pressure reference

`EPANET steady circulation graph` is an explicitly separate input mode for the existing pinned EPANET 2.2/WNTR 1.5.0 adapter. It requires zero junction withdrawals, DDA, exactly one fixed-speed sourced pump, one fixed-head reference with exactly one attached link, and a pipe return path from pump discharge to suction. Ordinary withdrawal models still require positive total design demand.

Run `python -m bsa.epanet examples/hvac-circulation/project.json --out runs/new-circulation`. Existing workflow kind `water_network` uses the same validated adapter. The pressure reference is a steady boundary idealization, not a physical expansion vessel or make-up-water design. EPANET reservoir/head, pump and pipe semantics follow the [official network model documentation](https://usepa.github.io/EPANET2.2/3_network_model.html). A zero net reference exchange and positive pump circulation must be demonstrated in the actual results, alongside existing native serialization, mass, pipe-energy, curve, pressure and velocity checks.

The synthetic reference example has a separately supplied two-point pump curve and two 30 m pipes with explicit K allowances, bores, roughness, fluid conventions and elevations. Actual execution gives about 3.0373 L/s and 4.53284 m pump head with zero reference exchange. Raising the reference head by 10 m changes nodal static pressures by 10 m without changing circulation flow in the regression test. This distinguishes pressurization from loop friction head. `docs/evidence/hvac-circulation` preserves the native INP/RPT/output and audited results.

This is a steady fully filled water hydraulic model. It does not establish thermal duty, required terminal flow, glycol or temperature-dependent properties, balancing/control-valve performance, heat-exchanger losses, pump efficiency/electric input, NPSH, expansion/air management or full HVAC/regulatory acceptance. No electrical power is inferred. IFC binding, regulatory water-pipe checks and automatic sizing for this circulation mode remain separate pending integrations.
