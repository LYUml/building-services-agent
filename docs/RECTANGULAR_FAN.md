# Rectangular single-path fan operating point

`python -m bsa.rectangular_fan examples/rectangular-air/fan-project.json --curve examples/rectangular-air/fan-curve.json --out runs/new-fan` solves a supplied fixed-speed total-pressure curve against one level rectangular path. `python -m bsa.workflow execute examples/rectangular-air/fan-plan.json --out runs/new-fan-workflow` integrates the calculation and pending manual engineering review. Use workflow kind `rectangular_fan_operating_point` with explicit project/curve; native producer inheritance is supported for the scoped paths described below.

The terminal's original prescribed demand becomes the minimum design flow. Its total-pressure requirement remains a fixed boundary; flow becomes an unknown. Other nodes have zero withdrawals. Branches, loops, nonlevel paths and laminar/transition domains reject. Curve density/viscosity must match the network exactly within the existing relative tolerance. No density or speed correction is inferred. Supply pressure in the input budget is replaced by inlet total pressure plus fan total-pressure rise.

Curve model is `fixed-speed air fan; single fixed-total-pressure terminal; free flow`. Require `pressure_basis: fan total pressure rise`, sourced speed/fluid and strictly increasing flow/decreasing pressure points, positive in-domain bracket, explicit flow/pressure tolerances and iteration budget. Efficiency basis must be `not supplied`; static-pressure curves, water efficiency fields and extrapolation reject. Installation category/system effects, actual stable region, source authenticity and product applicability still need engineering evidence. This is not arbitrary fan-curve support or a certified fan selection.

Reuses the existing bsa.pump bounded interpolation/bisection through private solver hooks and the pinned MIT fluids 1.3.1 Colebrook rectangular actual-area/hydraulic-diameter pressure engine. The public liquid-pump solve contract is preserved. The final saved operating network is freshly recalculated; root residual, bracket width, minimum flow, upper-bracket velocity and node pressure checks must all pass. No tolerance widening or underflow clamping is applied. Unbracketed/budget failures retain their trace and do not create an operating network.

AMCA explains the [distinction between static and total fan-pressure curves](https://www.amca.org/educate/articles-and-technical-papers/amca-inmotion-articles/straightening-out-fan-curves.html) and [fan/system equilibrium](https://www.amca.org/assets/resources/public/2024%20AHR%20Expo%20presentations/05.-fan-and-system-curves-with-fan-energy-index-%28fei%29%2C-part-2-of-2.pdf). These are method references, not curve/product or Hong Kong acceptance evidence. No upstream fan engine is copied or new dependency added.
