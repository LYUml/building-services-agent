## Limits preserved by the objective

Source interpretation is a host AI responsibility; an explicit handoff is
required. This is not autonomous semantic design of arbitrary buildings.
Each optional profile still needs its declared packages and host engine paths.
A listed tool or an existing executable alone is not verified integration.
New saved MCP paths require a new connection; current-chat hot reload is not
claimed and no user application was restarted.

Synthetic examples are software/physics integration evidence, not real project
acceptance. Actual manufacturer photometry/ratings, survey/route applicability,
complete installed pressure, physical equipment/ports, full regulatory review,
CFD and construction certification retain their task-specific roadmap gaps.
The known exact-build EnergyPlus SQL-flag limitation and original warnings are
preserved in [native energy evidence](NATIVE_ENERGY_USABILITY.md). Thermal energy
is separate from electrical energy. No source fact, clause or rating was invented.

BSE3227 remains the existing coursework package awaiting user feedback; this
audit does not change it or infer acceptance. The broader multi-service roadmap
is preserved. The completed outcome here is normal use of the existing supported
workflows with explicit engineering/review limits.
