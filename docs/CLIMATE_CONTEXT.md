# Candidate station climate context

bsa.climate_context composes existing strict EPW source/calendar/field validation with pinned Ladybug Core 0.45.0 EPW and Sunpath APIs in the existing isolated Honeybee environment. No new dependency, solar-position engine or weather provider is introduced. The AGPL-3.0-only climate_worker.py and retained upstream license texts are under adapters/honeybee-scene; the external engine is not modified.

The public benchmark may compare a Chicago candidate weather context using the already attributed official EnergyPlus-bundled Chicago O'Hare TMY3 asset. This is not confirmation of the course-assigned city or selection of a project parcel. Station 725300, latitude 41.98, longitude -87.92, timezone -6 and elevation 201 m are weather-station metadata, not surveyed project coordinates. Source raw/gzip hashes, source years and flags are retained. Climate calendar 2025 is a chosen solar-geometry analysis calendar; TMY3 records combine source years 1977, 1978, 1979, 1980, 1981, 1985, 1986, 1987, 1989 and 2002, not actual 2025 weather.

Run standalone:

```powershell
.venv/Scripts/python -m bsa.climate_context --weather examples/annual-energy/USA_IL_Chicago-OHare.Intl.AP.725300_TMY3.epw.gz --basis benchmarks/mit-4401-2018/climate-decisions.json --out runs/new-chicago-context --python tools/honeybee-scene-runtime/Scripts/python.exe
```

The public runner with --honeybee-python now includes a climate_context task and scoped source requirement automatically. Generic workflow tasks accept weather and basis only, plus optional requires_pass/description; the runtime comes from the explicit CLI flag. Weather, settings, reused modules and worker/dependency pins are inventoried. Missing runtime leaves pending with no climate output folder. No task silently georeferences the IFC, selects a site or clears the original site-analysis package.

The worker imports EPW through Ladybug, then reconciles every temperature/RH/wind and GHI/DNI/DHI value against original source records. Ladybug cyclically shifts point-in-time fields during import; this adapter explicitly restores their EPW source-record order while radiation interval fields remain unchanged. Monthly groups use original EPW source months and hourly records, rather than silently moving a boundary record between months. Host-side independent CSV sums verify every monthly statistic and monthly/annual irradiation reconciliation. Missing/sentinel thermal, radiation or wind fields reject through existing read_weather before Ladybug can substitute zeros.

Solar positions use native Python datetime objects carrying the declared year, avoiding Ladybug DateTime's default reference-year substitution. Hourly samples are at local-standard interval midpoints (00:30..23:30), no daylight saving, with true-north clockwise azimuth. Seasonal curves sample March/June/September/December 21 every 15 minutes. The source NOAA-based Ladybug solar implementation is reused; range/calendar and broad latitude/solstice sanity checks do not certify ephemeris accuracy. Above-horizon midpoint count is not measured sunshine duration or site daylight availability. No solar radiation transposition, obstruction/shading or building load is calculated.

Actual runs/chicago-climate-v1 covers 8760 records. Annual source GHI/DNI/DHI sums are respectively 1406.646 / 1294.257 / 660.253 kWh/m2. These are incident meteorological irradiation components on their defined reference planes, not facade absorption, PV yield, lux, thermal demand or electrical energy. Source-month January mean dry bulb is -4.6465 C and July mean is 24.1348 C. The plotted envelope shows source hourly minima/maxima, not a statistical confidence band or climate-change/design-temperature prediction.
